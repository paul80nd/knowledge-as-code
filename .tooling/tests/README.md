# `.tooling/tests` — the kac golden-file suite

`kac-tests` runs `kac` against deliberately-broken (and deliberately-clean) mini-wikis and diffs the findings against a
committed golden. It is an **integration** suite: it exercises the real rules end to end, not the C# internals. It is one
of three test layers — the unit tests (`kac.tests`) and Reqnroll feature tests (`kac.features`) live alongside; see
[`../README.md`](../README.md#tests).

```bash
dotnet run .tooling/kac-tests.cs                 # run every scenario, fail on any mismatch
dotnet run .tooling/kac-tests.cs -- clean        # run only scenarios whose name contains "clean"
dotnet run .tooling/kac-tests.cs -- --update     # regenerate every golden from current kac output
```

Exit `0` when every scenario matches its golden; `1` on a mismatch, a missing golden, a golden that references a
check id `kac` no longer emits, stale generated output, or a reachable check with no fixture.

## How a scenario runs

Each `fixtures/<scenario>/` is a mini-wiki minus its schema. A `mode` file (absent ⇒ `validate`) selects what is
asserted:

```
fixtures/
  clean/                                  # mode: validate (default)
    corpus/adrs/0001-clean-baseline.md    # the documents under test
    expected.json                         # the golden — the exact findings kac should produce
  index/                                  # mode: index
    mode                                  # "index"
    corpus/adrs/0001-first-decision.md    # source ADRs
    corpus/adrs.md                        # type page with the BEGIN/END GENERATED markers
    corpus/adrs/INDEX.md                  # committed generated output — the golden
  index-stale/                            # mode: index-stale
    mode                                  # "index-stale"
    expected-stale.txt                    # files `index --check` must report as stale
    corpus/...                            # a deliberately out-of-date INDEX.md
```

For each scenario the runner assembles a throwaway repo root in the system temp dir: it copies the **real**
`.schema/` in, drops the scenario's `corpus/` on top, and runs `kac` against it. That the schema is
copied fresh each run (never a committed copy) is deliberate — the suite tests the **production** rules, so a schema
change that alters behaviour surfaces here as a diff. The temp root is not a git repo, so kac's discovery falls back to
a filesystem walk and paths stay corpus-relative — no temp path leaks into a golden.

The three modes:

- **`validate`** — run `kac validate --json`, diff the findings against `expected.json`. Contributes to check coverage.
- **`index`** — the corpus already contains the correct generated files (`adrs/INDEX.md` and the spliced `adrs.md`);
  the run asserts `kac index --check` finds them fresh (exit 0). The committed generated files *are* the golden —
  reviewable in git, regenerated by `--update`. A generator change makes the run fail until the golden is refreshed.
- **`index-stale`** — the corpus is deliberately out of date; the run asserts `kac index --check` catches it (exit 1)
  and names the files listed in `expected-stale.txt`. `--update` leaves this fixture untouched.

## Writing a scenario

1. Create `fixtures/<name>/corpus/<type>/<doc>.md` with the defects (or the valid document) you want to pin.
2. Run `dotnet run .tooling/kac-tests.cs -- --update <name>` to generate `expected.json`.
3. **Read the golden.** `--update` captures whatever kac currently emits; the review step is where you confirm those are
   the findings you intended. Commit the corpus and the golden together.

Because a golden captures the **whole** findings set for its corpus, an accidental extra finding elsewhere in the
corpus shows up as a diff — that is the point, not a nuisance. Keep scenarios coarse (one dense corpus per theme) rather
than one file per rule: each scenario is a separate `kac` process, so a file-per-rule sprawl is slower for no gain, and
cross-document rules (`id-unique`, `reciprocal`, `related-matches-section`) need related documents in one corpus anyway.

For a **generation** scenario, add a `mode` file, author the source ADRs and a type page carrying the `BEGIN/END
GENERATED` markers, then run `--update <name>`: the runner runs `kac index` in a temp assembled from the corpus and
copies the generated files (`INDEX.md`, the spliced type page) back into `corpus/`. Review and commit them — they are
the golden.

## Coverage

On a full run the suite compares the checks exercised by the goldens against `kac checks` — the authoritative catalogue
of every rule `kac` implements. The gate is now enforced: **every reachable check must have a fixture**, or the run
fails. Two escape hatches keep it honest — a check that appears in a golden but is missing from the catalogue fails too
(a rename left a stale golden), and a check that no discovered document can reach is listed as `unreachable` and
excluded from the gate. Adding a new rule therefore means adding a scenario that exercises it, or CI goes red.

## Current scenarios

Every reachable check is covered (**29/30**; only the unreachable `type` is not — see below).

| Scenario            | Asserts                                                                                          |
|---------------------|--------------------------------------------------------------------------------------------------|
| `clean`             | A fully valid ADR produces **zero** findings — the false-positive guard.                         |
| `broken-frontmatter`| One ADR with a valid body isolates the frontmatter rules: `unknown-key`, `key-order`, `required-field`, `tier-matches-type`, `date-quoted`, `date-format`, `bare-key`. |
| `broken-structure`  | Six ADRs, one defect cluster each: `slug-length` + `h1-pattern`; `id-matches-filename` + `h1-matches-id` + `required-section`; `h1` (+ the `y-statement` warning it forces); `id-prefix`; `id-format`; `filename-pattern`. |
| `broken-values`     | Three ADRs for the frontmatter value-type rules: `enum` + `enum-lowercase` (an out-of-range, capitalised status); `list` (a scalar where a sequence is required); `frontmatter-parses` (an unterminated quote — this one short-circuits every other check). |
| `graph`             | Three related ADRs for the cross-document and reference rules: `link-resolves`, `undefined-label`, `bracket-literal`, `reciprocal`, `related-matches-section`, and `id-unique` (with `id-matches-filename` alongside, which is unavoidable — a duplicate id in a differently-numbered file cannot also match its filename). |
| `warnings`          | One otherwise-valid ADR carrying only warnings: `alternatives-verdict` (an open alternative) and `unused-definition` (a link definition nothing references). Asserts the run stays at exit 0. |
| `index`             | Two ADRs (one accepted, one proposed) and a type page with the generated-block markers. Asserts `index --check` finds the committed `adrs/INDEX.md` and spliced `adrs.md` fresh — pinning both the index table (populated and empty `decided-on` cells) and the `schema-adrs` / `checks-adrs` blocks. |
| `index-stale`       | The same corpus with a row dropped from `INDEX.md`. Asserts `index --check` detects the staleness (exit 1) and names `adrs/INDEX.md`. |

### Known validator gaps surfaced by the suite

- **`type`** fires only for a document whose folder maps to no schema, but discovery excludes non-type folders, so no
  discovered document can reach it — effectively unreachable. It is listed as `unreachable` by the coverage gate rather
  than demanded of a fixture.

> An earlier gap — `undefined-label`/`bracket-literal` only catching an *escaped* `\[adr-0099]` because Markdig
> fragments an unescaped `[` into its own literal inline — was fixed by rejoining each run of consecutive literal
> inlines before scanning (`ScanContainer` in `kac.core/Document.cs`). The `graph` scenario now covers both from the natural
> unescaped form.
