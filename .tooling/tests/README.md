# `.tooling/tests` — the kac golden-file suite

`kac-tests` runs `kac` against deliberately-broken (and deliberately-clean) mini-corpora and diffs the findings against
a committed golden. It is an **integration** suite: it exercises the real rules end to end, not the C# internals. The
unit tests (`kac.tests`) and the Reqnroll behaviour specs (`kac.features`) live alongside it — see
[`../README.md`](../README.md#tests) for what each layer is for.

```bash
dotnet run .tooling/kac-tests.cs                 # run every scenario, fail on any mismatch
dotnet run .tooling/kac-tests.cs -- clean        # run only scenarios whose name contains "clean"
dotnet run .tooling/kac-tests.cs -- --update     # regenerate every golden from current kac output
```

Exit `0` when every scenario matches its golden; `1` on a mismatch, a missing golden, a golden that references a check
id `kac` no longer emits, stale generated output, or a reachable check with no fixture.

## How a scenario runs

Each `fixtures/<scenario>/` is a mini-corpus minus its schema. A `mode` file (absent ⇒ `validate`) selects what is
asserted:

```
fixtures/
  clean/                                  # mode: validate (default)
    corpus/adrs/0001-clean-baseline.md    # the documents under test
    expected.json                         # the golden — the exact findings kac should produce
  index/                                  # mode: index
    mode                                  # "index"
    corpus/adrs/0001-first-decision.md    # source ADRs
    corpus/adrs.md                        # type page with the BEGIN/END GENERATED markers
    corpus/adrs/_index.md                 # committed generated output — the golden
  index-stale/                            # mode: index-stale
    mode                                  # "index-stale"
    expected-stale.txt                    # files `index --check` must report as stale
    corpus/...                            # a deliberately out-of-date _index.md
```

For each scenario the runner assembles a throwaway repo root in the system temp dir: it copies the **real**
`.schema/` in, drops the scenario's `corpus/` on top, and runs `kac` against it. That the schema is copied fresh each
run (never a committed copy) is deliberate — the suite tests the **production** rules, so a schema change that alters
behaviour surfaces here as a diff. The temp root is not a git repo, so kac's discovery falls back to a filesystem walk
and paths stay corpus-relative: no temp path leaks into a golden.

The modes:

- **`validate`** — run `kac validate --json`, diff the findings against `expected.json`. Contributes to check coverage.
- **`index`** — the corpus already contains the correct generated files (`adrs/_index.md` and the spliced `adrs.md`);
  the run asserts `kac index --check` finds them fresh (exit 0). The committed generated files *are* the golden —
  reviewable in git, regenerated by `--update`. A generator change makes the run fail until the golden is refreshed.
- **`index-stale`** — the corpus is deliberately out of date; the run asserts `kac index --check` catches it (exit 1)
  and names the files listed in `expected-stale.txt`. `--update` leaves this fixture untouched.
- **`mechanism`** — the fixture holds a `corpus/` and a `reference/`, each assembled over the real `.schema/` and
  `manifest.yaml`. The run asserts `kac mechanism --check --against <reference>` names every line of
  `expected-drift.txt` and exits 1; with no such file, that the shared layers are in step and it exits 0.
- **`sync`** — the same two trees through `kac mechanism --sync`, the one mode that writes. It asserts the tree the
  command left rather than only what it printed: `expected-sync.txt` names lines the output must carry,
  `expected-files.txt` paths that must be there afterwards, and `expected-content.txt` `<path> :: <text>` pairs each
  file must say. A `!` prefix on a line in either file inverts it. `corpus-schema.txt` names the type schema files the
  local side holds *before* the sync — the half-adopted state the real `.schema/` cannot express.
- **`export`** — `kac export` over the fixture corpus, asserting the tree it wrote in the same three files `sync` uses,
  with `expected-export.txt` in place of `expected-sync.txt`. `export-type`, where present, names the type to pass to
  `--type`. The run happens twice: the second is over an output seeded with a file no record backs, which asserts the
  overwrite is delete-then-write. The temp root is not a git repository, so no ref resolves and no link is written —
  the fixture therefore pins the corpus-publishes-nowhere path, and the link forms belong to the unit layer, which can
  supply a ref.

Only `validate` runs the validator, so a new check cannot affect the rest.

## Writing a scenario

1. Create `fixtures/<name>/corpus/<type>/<doc>.md` with the defects (or the valid document) you want to pin.
2. Run `dotnet run .tooling/kac-tests.cs -- --update <name>` to generate `expected.json`.
3. **Read the golden.** `--update` captures whatever kac currently emits; the review step is where you confirm those are
   the findings you intended. Commit the corpus and the golden together.

Because a golden captures the **whole** findings set for its corpus, an accidental extra finding elsewhere in the corpus
shows up as a diff, which is the point. Keep scenarios coarse (one dense corpus per theme) rather than one file per
rule: each scenario is a separate `kac` process, so a file-per-rule sprawl is slower for no gain, and cross-document
rules (`id-unique`, `reciprocal`, `related-matches-section`) need related documents in one corpus anyway.

For a **generation** scenario, add a `mode` file, author the source ADRs and a type page carrying the `BEGIN/END
GENERATED` markers, then run `--update <name>`: the runner runs `kac index` in a temp assembled from the corpus and
copies the generated files (`_index.md`, the spliced type page) back into `corpus/`. Read those files, then commit them
with the corpus.

## Coverage

On a full run the suite compares the checks exercised by the goldens against `kac checks` — the authoritative catalogue
of every rule `kac` implements. The gate is enforced: **every reachable check must have a fixture**, or the run fails.
It holds in both directions, so a check named in a golden that the catalogue does not carry fails too, which is a rename
that left a stale golden. A check no discovered document can reach is listed as `unreachable` and excluded. Adding a new
rule therefore means adding a scenario that exercises it, or CI goes red.

**The catalogue is a property of a corpus, not of the tool.** `CheckCatalogue.For(schema)` appends each expression
rule's `(id, severity, description)` to the core checks, which is why `Commands.Checks` takes the repo root — and why a
rule declared in YAML cannot ship without a fixture any more than a C# check can.

**The gate reads ids, not branches.** `y-statement-present` reports several faults under one id — an absent block-quote,
a missing move, a Y-statement past `max-words` — and a fixture for any one of them satisfies it. A rule with more than
one way to fail needs a fixture for each, or unit tests beside its rule class for the branches a second fixture would
only duplicate.

**Standing a rule up costs more in fixtures than in schema.** A rule on a type this suite has not met yet needs that
type stood up here — a page, a template and a record — which runs to an order of magnitude more lines than the YAML
declaring the rule. That is not a cost of writing rules as data: the gate demands a fixture however a check is
implemented. It is mostly one-off, too; once a type is present, the next rule on it is a record.

Every reachable check has a fixture, and a full run fails on one that does not — the run prints the tally. What a
scenario holds is best read from the fixture; what it is *for* is here.

### Known validator gaps surfaced by the suite

- **`type`** fires only for a document whose folder maps to no schema, but discovery excludes non-type folders, so no
  discovered document can reach it — effectively unreachable. It is listed as `unreachable` by the coverage gate rather
  than demanded of a fixture.
