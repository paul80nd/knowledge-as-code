U01. `kac update`. `new` only creates a corpus where none exists, and a `.corpus.yaml` at or above the working directory counts as one already being there. To take a newer framework into an existing corpus, run `update`.

U02. You still have to commit. `new` writes, generates, validates and stages the files, then stops before committing. Read what is staged and run `git commit` yourself.

U07. Azure Repos ignores the `pr:` trigger in the pipeline file. Add the pipeline as a branch policy: Project settings, then Repositories, then your repository, then Policies, then Branch Policies, then `main`, then Build Validation, then **+**. Select the pipeline and mark it Required.
Page: ci.md

U08. Exit code 2 means no corpus was found, not a fault in one. The step ran outside the corpus because there is no `.corpus.yaml` above its working directory. `cd` into the corpus and run it again.

U13. No. Below 1.0.0, `^0.16.0` only admits versions with the same minor (0.16.x), and `restore` never asks the registry whether a newer version exists. Change the range to `^0.17.0`, run restore, and commit the rewritten `resolved` line with it.

U14. A folder only holds the last package built, because `pack` rebuilds its output directory whole. So `restore` refuses a `resolved:` lock that names the earlier version. Move the lock along with the range when the producer's version moves, or delete `resolved:` and let the next restore write it.
Page: cli/restore.md
