# Dry run: 16 October 2026

**This is a dry run of the method, not a result.** It ran the trial over `examples/engineering`, an example corpus
that one person wrote to exercise the framework. Nobody adopted it, so no count here says whether a team writes its
knowledge down. The run shows that the script takes both readings and fills every field it can.

This run used method 1, which dated reading 1 to the corpus's first record. Method 2 dates it to the day it is taken.

## Counts checked by hand

Each of these looked wrong, or rested on a definition that could have misfired.

* **24 records on the first day.** The corpus came into its folder in one commit, `3b74b5ce`, which moved its records
  from elsewhere in the repository. The script reads that move as the day they were written, as
  [A corpus that moved](../README.md#a-corpus-that-moved) says. `git ls-tree` at `8e175613` lists 1 ADR, 1 glossary
  and 22 policies outside a `_` file, which matches.
* **`types_adopted` is 6 at both readings, over two different lists.** The corpus dropped `tools` in `67b93eaf` with
  no record in it, and adopted `reports` on 2026-09-08. Read the per-type fields, not the total, to see a change.
* **No standard on the first day.** The first standard landed on 2026-08-26, the day after. At reading 2 there are 12,
  which matches the 14 files in `standards/` less `_index.md` and `_template.md`.
* **No moves, and many renames.** Git lists renames under `policies/` on the default branch, as the policies were
  filed into subfolders and renamed. Each one stays inside `policies/`, so none is a move between types.
* **Two findings, and neither became a record.** #530 and #538 are the only issues labelled `kac:finding` whose block
  states `corpus: example-engineering`. Both are open, and no record cites either one. The one record with `sources`
  is a report, which cites corpora and no issue.
* **One author.** Every commit to the corpus folder has one author address, so `authors_not_owner` and `new_authors`
  are 0, and the days to a first record are empty.

## What the dry run could not test

The example corpus has one author, no moves between types, no finding that became a record, a tracker on GitHub and no
question log. So the script was also run over a throwaway repository built for the purpose, which is not kept. It had
a second author working on a merged branch, a record moved from `standards/` to `processes/`, a findings file for an
Azure DevOps tracker, and a question log. Every count it reported matched what the repository was built to contain. The
same check over `examples/dog-fooding` found 1 finding that became a record, #616, which `standards/versioning.md`
cites.

The Azure DevOps command in [the findings file](../README.md#the-findings-file) was not run. No Azure DevOps project was
reachable from this session.

## What the run changed in the method

The descriptor at the first snapshot is format 1, which states no `publishing.base`. The tracker could not be derived
from it. The script now reads the tracker from the descriptor in the working tree, and the adopted types from the
descriptor at the snapshot.
