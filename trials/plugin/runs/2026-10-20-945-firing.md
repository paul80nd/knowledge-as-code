# The #945 firing check

**The shortened descriptions did not stop a lookup firing.** Every one of the 22 sessions loaded a lookup skill: 21
loaded `standards-lookup`, and `audit-log-retention` loaded the lookup its grader accepts. Read by hand, 15 of the 18
house sessions that did the task complied, and 17 of 19 cited the rule. All 3 controls complied.

The run checks the second pull request of [story #945](https://github.com/paul80nd/knowledge-as-code/issues/945). It
rewrote the nine bundled skills other than `standards-lookup`, and cut each description to name each case that
triggers it once. A description is the one part of a skill every session sees, so a cut that loses a case shows as a
skill that does not fire.

The `go-service-dockerfile` call follows [the full pass](full-pass.md#adjudication): an `ARG` with no default fails.
A placeholder owner passes there, and a placeholder first action does not, because it tells nobody what to do.

## What the result shows

**No session was taken away from `standards-lookup`.** Each loaded one skill, and it was the lookup its case grades.

**The three misses lie outside the text this pull request changed.** Each session loaded only `standards-lookup`,
which this branch leaves as the pilot measured it. The other skills reached those sessions as descriptions alone.

* `pricing-call` is the miss #929 records, seen once in 3 in the pilot's rewrite arm and in
  [the hook arm](hook-arm.md#what-the-plugin-missed).
* `go-service-dockerfile` made the shipped skill's miss from the pilot, where the rewrite passed.
* `stock-alert-rules` passed in every earlier run.

## What the result does not show

* **Whether the compliance drop is real.** Each case ran once, so 3 misses in 18 cannot be told from chance.
* **Anything about when the seven untested skills fire.** No case asks for them.
