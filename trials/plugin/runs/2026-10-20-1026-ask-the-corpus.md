# The ask-the-corpus router

**A session reached the record a deviation or report question needed in 9 of 9 runs, once `controls-lookup` sent a
coverage question to the report.** `ask-the-corpus` fired in every run of the two deviation cases. Every
`uncovered-clauses` session loaded `controls-lookup` instead, and turned to the report only after that skill said to.

The run answers [story #1026](https://github.com/paul80nd/knowledge-as-code/issues/1026), and measures
[#1025](https://github.com/paul80nd/knowledge-as-code/issues/1025)'s decision on the same case. The
[assure run](2026-10-20-990-assure.md) found that no bundled skill read deviations or reports.

A session reached the record where it answered from it. For a report, that means it fetched the body, or gave the
report's title, date and link and said it could not read the limits, as #1025 decided.

* **The first build's coverage sessions read the report's index entry and rebuilt the count** from the standards and
  controls. One said the report could not be relied on, because it read `trust: unverified`.
* **The second build's coverage sessions tried to fetch the body.** Each made 2 `gh` calls, and 2 loaded
  `corpus-retrieval`. The sandbox blocked `raw.githubusercontent.com`, and `gh` had no login. Each reply then named the
  report, its date and its link, said it could not read the verdicts or the limits, and stated none.
* **The `sdk-before-change` fail** gives the deviation and how it closes, and leaves out its review date.

`complied` follows the assure run's reading, so a rebuilt count with a date and a limit from `controls-lookup` still
complies. Read it beside "Reached the record".

## Adjudication

4 verdicts were read by hand, and 3 overturned the graders. Each is in the build's `adjudication.tsv`.

* `uncovered-clauses`, first build, run 1, lists the clauses in short codes, which `task-names-a-clause` does not match.
* `uncovered-clauses`, second build, runs 2 and 3, give no clause id, because no body could be read.

## Grader fixes

* **`uncovered-clauses`, `task-names-a-clause`** read a clause id only, so a reply that could not fetch the report
  scored `no task`. It is now `task-names-a-clause--listed`, beside `--unfetched`, which matches a reply saying it
  could not read the report.
* **`uncovered-clauses`, `comply-limits--unread`** is a new alternative. It matches a reply saying it could not read
  the limits.
* **`deviations-due` and `uncovered-clauses`, `fired-lookup`** accept `ask-the-corpus` as well as a lookup.

`regrade.mjs` over both builds' kept sessions passes the 3 second-build sessions on the new graders, and none of the
first build's rebuilt counts. The 66 unchanged verdicts agree with the tool.

## What the result shows

**A skill already named for the question takes it, so the turn to a report has to sit in that skill.** The router
fired wherever no lookup claimed the question. `controls-lookup` claims "which rules nothing checks" in its
description, and kept doing so.

**A session told where the answer is follows #1025's rule when it cannot get there.** No reply inferred the report's
limits.

## What the result does not show

* **An answer from a fetched report body.** The sandbox blocked every fetch, so no session quoted the report's Limits.
* **The plugin's lead over any arm.** The run has no prose arm and no none arm.
* **The variance of more runs.** Each case ran 3 times on each build.
