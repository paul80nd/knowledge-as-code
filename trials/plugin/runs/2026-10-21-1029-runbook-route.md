# The runbook route

**On `goldens-red-what-first`, `ask-the-corpus` found the runbook by its search for the subject, and the score did not
move.** The plugin arm met it in 3 of 3 runs before the route and 3 of 3 after, and the none arm in 0 of 6. With
`runbooks.md`, every session named `Immediate actions`, gave the link and stated no steps. Before it, two of three
sessions padded the reply, one from `ctl-0009` and one from the exported `Symptoms`.

**`snapshot-tests-red-in-ci` did not test the matching `runbooks.md` asks for, because no session loaded it.** The
prompt reports a failure in words no runbook uses. All 6 sessions loaded `fix-lookup` and none loaded `ask-the-corpus`.
Each found the runbook from the shell, by adding "golden" and "CI" to a search for "snapshot", and cited it. The
plugin arm met the scenario in 2 of 3 runs before the route and 3 of 3 after. The one failure listed actions under
"What the runbook says to look for", which the export does not state as steps. Four of the other five replies gave
first steps of their own, built from the exported `Symptoms`. `runbooks.md` forbids that, and `fix-lookup` does not
mention it.

**The route stays.** A runbook's body stays behind on purpose, as a report's does, and invented steps are where a
missing body costs most.

[Story #1029](https://github.com/paul80nd/knowledge-as-code/issues/1029) asks for a route wherever a case shows the
need. The run writes two question-only cases for runbooks, runs each on a plugin bundled before the route and on one
bundled after it, and records why adrs, tools, services and postmortems take no route.

## The cases

| Case                       | Prompt                                                                                                         | `cite-`                |
|----------------------------|----------------------------------------------------------------------------------------------------------------|------------------------|
| `goldens-red-what-first`   | The golden suite passes on my machine and fails in CI. What do I do first?                                    | `rbk-goldens-disagree` |
| `snapshot-tests-red-in-ci` | The snapshot checks keep failing in the pipeline, but they're fine when I run them on my laptop. Where do I start? | `rbk-goldens-disagree` |

**Neither prompt names a record, rule, type or corpus.** Each scaffold writes a README and nothing else, so it gives
the none arm neither the runbook nor `GITHUB_ACTIONS`. Neither case has a `task-` grader, because the task is the
reply.

**`snapshot-tests-red-in-ci` shares no noun with the runbook.** No runbook in the export contains "snapshot",
"checks", "pipeline" or "laptop". The runbook's `Symptoms` contain "tests", "suite" and "pass", so the prompt avoids
them. Its README does not name `kac`, which the runbook's `applies-to` contains.

`comply-steps--` has two alternatives in each case. `--link` finds `runbooks/goldens-disagree.md` in the reply.
`--untravelled` finds a sentence saying the steps did not come, were left out, or could not be fetched. The sandbox
blocks the fetch `corpus-retrieval` makes, so the steps are judged by the rule #1025 set for a report: a reply that
cannot fetch states none of the runbook's. A reply that presents steps as the runbook's without the fetch fails by
hand, whatever the graders say. Advice the reply gives as its own passes, and the record notes it.

before I change X" section.** That section searches `corpus/` for the subject, and reads a type no row covers whole,
quoting it and linking it. Each session searched `corpus/` for `golden`, read `rbk-goldens-disagree.json`, and loaded
`corpus-retrieval`.

**On `snapshot-tests-red-in-ci`, every session read the question as an error to look up, and loaded `fix-lookup`.**
`fix-lookup` found no fix, and each session then searched `corpus/` from the shell. Every search named "golden" beside
"snapshot", and every one also searched for "ci" or "CI", which the prompt does not say. One reply said "Snapshots
are called goldens in this corpus". The model supplied both words. Nothing in the plugin did.

**`fix-lookup` has no pointer to runbooks.** A failure in progress reads to a session as a problem to look up, which
is the case `fix-lookup`'s description names. The rule against stating steps sits in `runbooks.md`, and only
`ask-the-corpus` points at that file. So no session in this case read it.

## What the result does not show

* **Whether `runbooks.md` matches a symptom the subject search misses.** No session in `snapshot-tests-red-in-ci`
  loaded the file, and the model supplied "golden" and "CI" itself.
* **Whether a session follows the fetched steps in order.** The sandbox blocks the fetch, so no session read them.
* **Whether the prose or hook arm does as well.** The run has neither, and `snapshot-tests-red-in-ci` has no none arm.
