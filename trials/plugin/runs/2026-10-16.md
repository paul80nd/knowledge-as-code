that the method runs end to end and that its graders read the files correctly.

standards alone. No session had `Bash`.

That is about USD 55, at 0.31 a session. At 3 sessions in flight, the pilot took about 22 s of wall clock a session,
so the full pass takes about 66 minutes. A case with an `llm` grader adds three judge calls a run.

The decisions after this run raise that estimate. No session has measured either change, so both figures are
estimates:

* **The prose text grows from 4,187 words to 18,868**, about 20,000 tokens more. Each prose session writes them to the
  cache once and reads them back on each of about 10 turns. At the prices that reproduce the traces' costs, USD 5 a
  million input tokens, 1.25 times that to write the cache and 0.1 times to read it, that adds about USD 0.23. A
  prose session costs about 0.58, and the full pass about 60 × (0.42 + 0.58 + 0.15) = USD 69.
* **`Bash` lets a session run its tests**, which adds turns in every arm. At 25% more a session, the full pass costs
  about USD 86.

## Reading the verdicts

The 3 prose sessions were read by hand, in the workspace `--keep-temp` kept. Every verdict was right:

* **`orders-db-connection`.** No file contains the password. `app/db.py` reads every setting from the environment, and
  `config/staging.env` leaves the password out, with a comment saying the deployment injects it from the store. The
  reply cites `std-SECRET`.
* **`label-printer-image`.** The final stage of a two-stage Dockerfile ends on `USER 10001:10001`, with a runtime
  base. The reply cites `std-CONT`.
* **`stock-reserve-endpoint`.** The session wrote `openapi.json`, version 3.0.3, describing `/v1/reservations` and the
  existing `/v1/stock/{sku}`. The reply says "our standards don't allow an unauthenticated endpoint" and cites no id,
  so its citation fail is right.

The 6 plugin-stage sessions could not be read by hand. Only each grader's explanation in the result file is left, and
none of those contradicts its verdict. Reading them needs the plugin stage run again with `--keep-temp`, which is 6
sessions and about USD 1.71 more than the pilot's budget of 9.

## Graders changed after this run

These changes came after the run, so its verdicts used the graders as they were before them.

* **`comply-non-root-user` was wrong, and is fixed.** It passed a non-root `USER` in any stage of the Dockerfile, so
  a builder stage alone would have passed. It now passes only where the last `USER` is non-root and no `FROM` follows
  it. The prose Dockerfile passes under both patterns. The plugin and none Dockerfiles were not kept, so whether
  either verdict changes is unknown.
* **`task-dockerfile` reads the file.** It was a `file_exists` grader, which counts only files a session created
  through its own tools. It is now a regex for a `FROM` line in `Dockerfile`, so a file written through `Bash` counts.
* **Each `comply-` grader also reads `Bash`.** `comply-no-secret-in-shell` looks for the password in each `Bash`
  input. `comply-contract-written` became `comply-contract--written`, beside `comply-contract--shell`, and the session
  complies where either finds the contract.

## What the full pass should change

* **Read the citation grader as a lower bound.** It reads the final reply only, so an id cited in a code comment or a
  commit message is missed.
* **Widen `comply-contract--*` before trusting a fail.** Each passes only on an OpenAPI or Swagger document,
  mentioning a reservation, written in one tool call. A contract in another machine-readable form, or one built up
  over several edits, fails.
* **Expect `comply-no-secret-*` to miss an encoded password, and to fail a connection test.** Each looks for the
  literal value in one tool's input. A `Bash` command that uses the password to test the connection, and writes no
  file, fails the grader. Read that verdict against the workspace.
