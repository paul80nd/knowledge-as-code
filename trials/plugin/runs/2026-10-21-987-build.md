# The #987 build cases

**Two of the three build scenarios met their threshold, and one failed in every run of both arms.**

* `loan-history` met it in 3 of 3 plugin runs and 0 of 3 none runs. Every plugin route left out loans returned more
  than two years ago, and every none route returned them all.
* `patron-reminders` met it in 3 of 3 runs of both arms. Every session named its new fields `Borrower`, because the
  scaffold's `HoldReadyEvent` already does.
* `second-package-unscanned` met it in 0 of 3 runs of both arms. No workflow scanned the package, and no reply raised
  `pol-TRUS.MALWARE`.

The run gives each of the three `@proposed` scenarios in [`build.feature`](../../use-cases/build.feature) its first
baseline. It writes the three cases [story #987](https://github.com/paul80nd/knowledge-as-code/issues/987) asks for, and
runs each in the plugin arm and the none arm. Each case asks for code, so each is graded on what the session wrote.

## The cases

| Case                       | Prompt asks for                                          | `cite-`                 | `comply-`                                                                |
|----------------------------|----------------------------------------------------------|-------------------------|--------------------------------------------------------------------------|
| `second-package-unscanned` | a workflow that publishes a new tool to nuget.org on tag | `pol-TRUS`              | the workflow runs a malware scan, or the reply raises `pol-TRUS.MALWARE` |
| `loan-history`             | `GET /borrowers/{card}/loans/history` over `CIRC_LOAN`   | `dat-loans`             | the code cuts off at two years, or the reply cites dat-loans             |
| `patron-reminders`         | a reminder to patrons three days before a loan is due    | `gls-example-libraries` | a new name says `Borrower`, and no input says `patron`                   |

**`second-package-unscanned` builds kac-lint**, a new .NET global tool in its own repository that no record covers.
The prompt names neither scanning nor the corpus. Whether a reply cites `dev-package-unscanned` as covering kac-lint
is judged by hand, because a reply may cite the deviation correctly as covering kac alone.

**`patron-reminders` reuses the notices scaffold** from `text-the-borrower`. `comply-no-patron-` is three `tool_used`
graders with `max: 0`, one each for `Write`, `Edit` and `Bash`, the form `ca1848-build-break` uses. A comment saying
patron fails it.

`fired-` accepts any lookup skill or `ask-the-corpus`, as in #986.

## Grader fixes

**`comply-no-patron-shell` failed a session that searched for the word.** Plugin run 3 ran `grep -i -E
'...|borrower|patron'` over the glossary, and wrote no name saying patron. The grader now skips a `Bash` input that
runs `grep` or `rg`. `regrade.mjs` over both kept batches agreed with the tool on every other verdict, 108 in all, and
passed that session on the fixed grader. The run is scored on the adjudication, as the README says, and not on the
fixed grader.

`comply-borrower--written` passes a `Write` whose content says `Borrower` anywhere. Every session it passed added a
new field or type saying it, so it decided no verdict wrongly here. Read it by hand in a later run.

## How each session reached the record

This section is evidence for [#1029](https://github.com/paul80nd/knowledge-as-code/issues/1029).

**Every plugin session loaded one skill, then read the records' JSON under `corpus/` from the shell.** No skill read
the record for it.

| Case                       | Skill loaded                           | Then read                                                                                                     |
|----------------------------|----------------------------------------|---------------------------------------------------------------------------------------------------------------|
| `loan-history`             | `ask-the-corpus`                       | `data/dat-loans.json` and `services/svc-lending.json`, with `dat-borrowers` or `ofr-borrowing`                |
| `patron-reminders`         | `ask-the-corpus`                       | `services/svc-notices.json`, `data/dat-loans.json` and the integrations, and in 2 runs `glossary/terms.jsonl` |
| `second-package-unscanned` | `process-lookup` or `standards-lookup` | `standards/rules.jsonl` or `std-CI.json`, `tools/tol-nuget-login.json` and the nuget runbook                  |

**No `second-package-unscanned` session opened `policies/`.** Each loaded a process or standards lookup for a publish
workflow, and followed std-CI. The malware clause is a policy clause, and no standard here covers it: the coverage
report lists `MALWARE` as a gap that only `dev-package-unscanned` touches. A session that asks how to publish is sent
to std-CI, which says nothing on scanning.

**`ask-the-corpus` sent each library session to search `corpus/` for the thing it was changing.** In `loan-history`
that search found `dat-loans` every time. In `patron-reminders` it found the services and data records, and the
glossary only where the session searched `terms.jsonl` for a word in the prompt.

## What the result does not show

* **Whether `patron-reminders` measures the glossary.** The scaffold names `Borrower` already, so the none arm complies
  by copying it. A scaffold naming the person nowhere would separate the arms.
* **Whether the plugin can deliver a policy clause to a build task with no standard covering it.**
  `second-package-unscanned` failed in both arms, and no plugin session read a policy.
* **Whether the prose or hook arm does better.** The run has neither.
