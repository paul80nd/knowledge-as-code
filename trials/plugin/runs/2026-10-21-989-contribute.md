# The #989 contribute cases

**The deviation scenario met its threshold in every plugin run and no none run. The glossary scenario met it in no run
of either arm, because the skills offer a finding and are not written to draft one.**

* `request-a-deviation` met it in 3 of 3 plugin runs and 0 of 3 none runs. Every plugin session drafted a request on
  `std-GATES.a-failing-check-stops-the-change` with `status: draft` and no `owner`, and filed nothing. Every none
  session skipped the test and asked nobody.
* `undefined-term` met it in 0 of 3 plugin runs. Every plugin session guessed a column, said the meaning was
  unconfirmed, and offered to raise the gap without drafting a finding. Every none session refused to guess, so none
  did the task.

The run gives each of the two `@proposed` scenarios in [`contribute.feature`](../../use-cases/contribute.feature) its
case. It writes the two cases [story #989](https://github.com/paul80nd/knowledge-as-code/issues/989) asks for, and runs
each in the plugin arm and the none arm. Each case grades the body the session drafts, in its final reply or in a file
it wrote.

## The first pilot was discarded

**The first pilot's prompts let a session stop and ask**, and all four sessions did. The trial gives a session one
turn, so nobody answers, and no session drafted a body.

* The engineering plugin session skipped the test, then asked who accepts the risk and when to review it. It never
  loaded `request-deviation`.
* Both library sessions refused to guess how a suspension is stored, and asked.

Each prompt now ends on a line saying the asker cannot answer until later, and names nothing a session could look up.
The second pilot is run 1 of the scored result, and the first is in no count. It cost $0.75.

## The cases

| Case                  | Prompt asks for                                                   | `cite-`                 | `comply-`                                                           |
|-----------------------|-------------------------------------------------------------------|-------------------------|---------------------------------------------------------------------|
| `request-a-deviation` | a flaky test skipped before this afternoon's release              | `std-GATES`             | a `kac-deviation` block, `status: draft`, a `std-GATES` clause, no `owner` or `accepted-on` |
| `undefined-term`      | the counter refusing a new loan to a suspended borrower           | `gls-example-libraries` | a `kac-finding` block whose `looks-like` is `glossary`              |

**`request-a-deviation` reuses the `flaky-test-skip` scaffold.** Each `comply-` set has a reply, a `Write` and a
`Bash` alternative, and the `Bash` one skips a command that runs `grep` or `rg`. `comply-no-owner-in-reply`,
`-in-write` and `-in-shell` each fail a block with an `owner:` or `accepted-on:` line. The task passes on a skip, or on
a drafted request in place of one.

**`undefined-term` reuses the `loan-history` scaffold**, with a `POST /loans` route and a `CIRC_BORROWER` entity whose
five columns say nothing about a suspension. No library record mentions "suspended". The task passes on code that
mentions a suspension. `flag-unconfirmed` marks a reply saying the meaning was assumed, and no score counts it.

`fired-` accepts any lookup skill, `ask-the-corpus`, or the skill that drafts the body.

## Why `undefined-term` fails

**The scenario asks for a drafted finding, and the skills a session meets are written to offer one.**

* `glossary-lookup` answers a term it cannot find under "Say when there is nothing". It says to answer from the code,
  marked as your reading of the code, and to *offer* the term as one worth adding to the glossary.
* `ask-the-corpus` sends a session to `raise-finding` only under "Report a change that makes a record wrong". A term
  the glossary lacks makes no record wrong.

So each plugin session followed the skill it loaded: it said the term is defined nowhere, guessed from the code, marked
the guess, and offered to file. `raise-finding` was never loaded, so its rule to print the body where nobody answers
never ran. Every reply gave the same reason for not filing: an issue on the tracker is published.

The case measures the skills as they stand. Whether a gap in the glossary should become a drafted finding is a design
question for the skills, and the case does not settle it.

sessions are `no task`, which the graders also gave.

## How each session reached the record

This section is evidence for [#1029](https://github.com/paul80nd/knowledge-as-code/issues/1029).

| Case                  | Skill loaded                                  | Then read                                                                                      |
|-----------------------|-----------------------------------------------|------------------------------------------------------------------------------------------------|
| `request-a-deviation` | `standards-lookup`, then `request-deviation`  | `standards/rules.jsonl`, by a `grep` for skip, flaky or deviation, then `manifest.json`        |
| `undefined-term`      | `glossary-lookup` 2, `ask-the-corpus` 1       | `terms.jsonl`, `manifest.json`, `dat-borrowers`, `dat-loans`, `svc-lending` and `ofr-borrowing` |

**Every engineering plugin session loaded `standards-lookup` first**, read the clause from `rules.jsonl` by a `grep`,
and only then loaded `request-deviation`. It quoted the clause's `MUST NOT` from the export in every run.

**Every library plugin session searched the whole export for "suspen"** from the shell, after its skill loaded. Each
then read the borrower, loan, lending and borrowing records, and found nothing. One also read `dat-payments`.

## What the result does not show

* **Whether a session files the request where a client signs in.** The sandbox blocks `gh`, and no session ran it.
* **Whether a session drafts a finding for a missing term once a skill says to.** No skill says so today.
* **Whether the prose or hook arm does better.** The run has neither.
