# The #986 design cases

**All five design scenarios met their threshold, each in 3 of 3 runs.** Every design either followed the record or cited
it and said why it departed:

* `adr-ruled-out` made superseding adr-0002 the first step.
* `public-path-between-services` cited `pol-MEXP.PRIVATE` with its reason, and requested no deviation.
* `authorisation-extra-call` showed the new call breaks nfr-0001's 800ms and put a revised target to its owner.
* `new-command-line-verb` chose the approved parser.
* `text-the-borrower` said the SMS integration is retired.

The run gives each scenario in [`design.feature`](../../use-cases/design.feature) its first baseline. It writes the five
cases [story #986](https://github.com/paul80nd/knowledge-as-code/issues/986) asks for, and runs each in the plugin arm
alone. Each case asks for a design in `docs/design.md`, so each is graded on that file and not on code.

The engineering and dog-fooding stages ran with `--case`, because `stage.sh` stages every case in the folder. Before
each consumer restored, `.imports/` was deleted in `examples/payments` and `examples/dog-fooding`, and engineering was
packed again.

**The library stage changed between the pilot and the batch.** The library plugin ships no `hooks/build-index.json`,
because its bundle trims the build index, and `stage.sh` refused it. The pilot stage was copied by hand to the layout
`stage.sh` writes. `stage.sh` now warns and stages such a plugin. The batch ran from a stage it wrote. The two stages
hold the same files, and differ only in what the newer export put under `corpus/`.

**The library pilot ran on an export before `af7de1af`.** That commit corrected adr-0002's last consequence to say
nothing reconciles a payment with its hold. The pilot `adr-ruled-out` design quoted the old wording once, in a section
on the pay step it left out of scope. Its verdict rests on the Decision it quoted and the superseding ADR it asked for,
so the change could not have moved it. The batch designs read the corrected export.

## The cases

| Case                           | Prompt asks for a design that                        | `cite-`           | `comply-`                                                               |
|--------------------------------|------------------------------------------------------|-------------------|-------------------------------------------------------------------------|
| `adr-ruled-out`                | lets a borrower resume a half-finished reservation   | `adr-0002`        | the design cites adr-0002 and supersedes it, or follows it              |
| `public-path-between-services` | calls pricing over the public gateway, with a reason | `pol-MEXP`        | `pol-MEXP.PRIVATE` cited, or a private path; and no `request-deviation` |
| `authorisation-extra-call`     | adds a fraud screen ahead of the PSP                 | `nfr-0001`        | the design states 800ms, or cites nfr-0001                              |
| `new-command-line-verb`        | gives a new .NET tool its first verb                 | either `tol-` id  | Spectre.Console, or System.CommandLine called deprecated                |
| `text-the-borrower`            | texts a borrower when a hold is ready                | `itg-sms-notices` | the design says the integration is retired                              |

**A `task-` grader passes where `docs/design.md` exists and names the subject.** A `cite-` grader passes where the id
is in the final reply or in the design. **`comply-no-deviation-request` passes where no `request-deviation` skill call
was made.** It is a `tool_used` grader with `max: 0`, the form `ca1848-build-break` uses.

No bundled lookup reads `adrs/`, `nfrs/`, `tools/` or `integrations/`, so each `fired-` grader accepts any lookup skill
or `ask-the-corpus`.

## Grader fixes

None. Every verdict the graders gave agreed with the design read by hand.

Two alternatives pass on wording that does not show compliance. **`comply-adr--follows`** passed in all three
`adr-ruled-out` runs, because each design quoted adr-0002's "not supported". Each complied by asking for a
superseding ADR, which `comply-adr--supersedes` also found. **`comply-parser--departs`** passed in all three
`new-command-line-verb` runs, because each design called System.CommandLine deprecated while choosing Spectre. Neither
grader decided a verdict here. Read both by hand in a later run.

## How each session reached the record

This section is evidence for [#1029](https://github.com/paul80nd/knowledge-as-code/issues/1029).

**Every session loaded one skill, then read the record's JSON under `corpus/` from the shell.** No skill read the record
for it.

| Case                           | Skill loaded                           | Then read                                                          |
|--------------------------------|----------------------------------------|--------------------------------------------------------------------|
| `adr-ruled-out`                | `ask-the-corpus`                       | `adrs/adr-0002.json`, with the reservations service and offering   |
| `text-the-borrower`            | `ask-the-corpus`                       | `integrations/itg-sms-notices.json` and `itg-mail-delivery.json`   |
| `authorisation-extra-call`     | `ask-the-corpus` or `standards-lookup` | `nfrs/`, with the services and offerings                           |
| `new-command-line-verb`        | `ask-the-corpus` or `standards-lookup` | `tools/tol-system-commandline.json` and `tol-spectre-console.json` |
| `public-path-between-services` | `policy-lookup`                        | `policies/pol-MEXP.json` and `policies/clauses.jsonl`              |

`ask-the-corpus` sent each session that loaded it to search `corpus/` for the thing it was changing. The three sessions
that loaded `standards-lookup` opened `nfrs/` or `tools/` from the shell, with no skill pointing them there.

## What the result does not show

* **Whether the plugin leads an arm.** The run has no prose arm and no none arm.
* **Whether the cases are hard enough.** Every run met its scenario. A none arm would show how many of these designs a
  session writes without the records.
