This run compares `kac` with four families of offerings that solve a similar problem. Each family's notes cite every
claim with its source and the day it was read. This page states the findings, and each one links the notes behind it.

A corpus is one repository of knowledge records. A record is one Markdown document in it, with a declared type. The
plugin is the corpus packaged for Claude Code.

## Where `kac` leads

Most offerings check a file's shape, and some check its values. `kac` is the only offering read that checks one record
against another before merge.

* **A reference must resolve, before merge and offline.** Cortex's pull-request linter "does not verify the
  correctness of referenced data". Backstage's `catalog validate` needs an authenticated Backstage instance. OKF says
  "Consumers MUST tolerate broken links". Astro checks a reference only when a page renders. `kac validate` fails CI on
  an unresolved reference and on a reciprocal edge only one record states.
* **A rule has an id and a level.** A Cortex or OpsLevel check passes or fails an entity. A Cursor rule is free text.
  A `kac` rule such as `std-SECRET.STORE` is a clause an agent and a reviewer can cite.
* **A consumed corpus is versioned.** An OSCAL profile imports by `href`, with no version range or lock. A Claude
  Code plugin dependency takes a range but checks nothing in the content. `consumes:` takes a semver range, resolves
  a lock, and fails a citation the new version broke.
* **Policy, standard and control link in a checked chain.** OSCAL has the nearest chain, and the
  [decision records notes](2026-10-27/adr-compliance.md#the-chain-compared-with-kac) map it onto `kac`'s. No catalogue
  or agent context tool links a rule to the policy it implements or the check that proves it.

## What `kac` states wrongly

These findings are about `kac`'s own records and pages, so each one asks for a change here.

1. **The OKF links point to a frozen copy.** The `okf/` folder in `knowledge-catalog` says: "Stop using the copy under
   `okf/` in this repository. It is a frozen snapshot, no longer maintained". The spec now lives in
   [`open-knowledge-format`](https://github.com/GoogleCloudPlatform/open-knowledge-format). Seven tracked files cite
   the old copy, among them `.schema/reports.yaml`, `docs/reference/export.md` and each corpus's `lineage.md`.
2. **The trust tiers depart from OKF in two ways nothing states.** `docs/reference/export.md` leaves out "a
   verification taken before `generated.at`", and OKF says "`verified` is independent of `generated.at`". The same
   page and `docs/use/cli/report.md` say "agents alone" earn `machine-confirmed`, where OKF says "non-`human:` actors
   only". Then the page says "The three tiers are the Open Knowledge Format's". The `reports.yaml` divergence lists
   neither.
3. **`docs/framework/lineage.md` quotes an old ADR row.** It says "The ADR row reads:" and quotes an `alignment` and
   a `divergence` that no longer match `.schema/adrs.yaml`. The current row cites MADR 4, and the quoted one does not.
4. **The ADR lineage counts `rejected` as a divergence.** MADR 4 lists `proposed | rejected | accepted | deprecated |
   superseded`, the same five values in the same order. `rejected` diverges from Nygard and aligns with MADR 4.
   `deciders` against MADR 4's `decision-makers` is already #671.
5. **`.schema/controls.yaml` cites an OSCAL key that does not exist.** It says OSCAL "names who collected an
   observation in `origin-actor`". Neither the JSON outline nor the XML outline of the OSCAL 1.2.3 assessment results
   model uses that name. The JSON path is `observations/origins/actors`.
6. **The build index is not sent again after a compaction.** `template/.plugin/hooks/build-index` prints once per
   session id. Where a compaction keeps the session id, the marker stays and the hook stays silent. The breadcrumb's
   matcher lists `compact`, and the build index has none. This reading comes from the code. No trial has measured it.
7. **`docs/compared.md` leaves out developer portals and compliance as code.** `.schema/services.yaml` cites
   Backstage, Cortex and OpsLevel as prior art. A reader who already runs Backstage asks that comparison first.

## Claims that did not survive checking

Each family's notes keep what the agent wrote. These claims are wrong, and this review does not rely on them.

* **"A skill fix may never reach installed users."** The agent context notes say nothing moves the plugin's version
  when a skill changes. [std-VERS](../../../examples/dog-fooding/standards/versioning.md) says `content-version`
  **MUST** move where a change reaches a skill, a hook or the manifest its bundle includes.
* **"`immutable-after-accepted` may be unenforced."** The decision records notes found no `expr:` on it.
  `tooling/kac.core/Rules/HistoryRules.cs` enforces it.
* **"Path loading is left open in #993."** #993 is closed. It decided against a glob on a rule, because a glob filters
  out the cross-topic rules the build index exists for, and no run showed the index too noisy.
* **"`kac` measures with its own trials, not with `claude plugin eval`."** The [plugin trial](../../plugin/README.md)
  runs its arms through `claude plugin eval`.
* **"No page tells an organisation to use managed settings."** [Installing the
  plugin](../../../docs/use/installing-a-plugin.md) covers `extraKnownMarketplaces`, `enabledPlugins` and managed
  auto-update.

## What follows

The developer decided these on 2026-10-27, reviewing this page.

* **`kac` is the checked-content layer.** Delivery is a thin adapter, the Claude Code plugin today. `kac` closes a
  delivery gap by adopting what a platform offers, and builds no delivery stack of its own.
* **The trial tests the lead.** The plugin trial's `prose` arm gives an agent the same records as text, so it
  measures delivery. The trial plan names a second claim: `kac validate` catches faults a team would otherwise ship.
  The capture trial's fault log measures it, against what a tolerant tool such as OKF or Cortex would have let
  through.
* **A `kac` record is also an OKF document.** `kac` conforms as an OKF producer, and takes OKF's optional parts
  where they serve its aims. It does not read OKF bundles, because a consumer must tolerate what `kac` rejects. Each
  later run of this review diffs OKF's spec against the version this one read, which is 0.2.
* **Nothing is cut before the trial.** First, each unused surface the [surface measurement](../../surfaces/README.md)
  lists is tried against the example corpora, and used where it fits. Whatever the trial then shows unused goes, in
  #1165.
