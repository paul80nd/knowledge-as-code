# The question half, 2026-11-11

This run took the question half of the [scale trial](../README.md) on the corpus (one repository of knowledge records)
of 8 applications. It asked [the twelve questions](../questions.md) through the plugin, through the whole corpus as one
prose text, and with nothing. It also re-measured the size half at 8 applications.

## Reading

**Neither the plugin nor the prose text loses answers on the questions that reach across records.** Each answers them
at the rate it answers the one-record questions. At 8 applications, scale costs neither arm an answer.

**A prose answer costs about 20 times a plugin answer.** Every prose session costs $4.57, within a cent, whatever it
was asked. That is the text entering the context. A plugin session costs between $0.18 and $0.43, by how much it reads.

**The prose arm's one miss is a fault in the text, not in the session.** Question 2 asks when the Fir deviation is
reviewed. `trials/plugin/prose-claude-md.mjs` drops `review-by` with the other bookkeeping fields, so the text never
states the date. The session said the record gives no review date, which is true of what it read.

**The none arm answers only from general knowledge.** Its two passes on question 4 say no on general grounds and cite
no record. Its three graders' passes on question 9 recommend a random UUID for the key, which `std-IDEM.KEY` advises
against. `task-derive` now checks how the key is built, and it did not exist when this run graded.

**The text stops fitting at about 15 applications.** The pilot read the text of 2 applications as 225,948 tokens, and
this run reads the text of 8 as 577,619. Each application adds about 58,600 tokens on top of about 108,700 that do not
grow. A window of 1,000,000 tokens holds about 15 applications. No arm measured it.

**The plugin reads the corpus through `Bash` more than through its own tools.** 32 of the 36 plugin sessions called
`Bash`, 100 times in all: `cat` 33, `grep` 26, `python3` 12, `ls` 9, `jq` 6 and `sed` 6. They called `Read` 26 times and
`Grep` 28 times. `ask-the-corpus` fired 30 times and `policy-lookup` never, even on question 4, which asks about a
policy. Every plugin session fired some lookup.

**A runbook's steps do not travel.** The three plugin sessions on question 10 found the runbook and its severity, then
said the export carries only Symptoms and Impact. Each tried `gh` for the rest and found it signed out.

## The size half at 8 applications

The corpus of 8 applications validates with 0 errors and 0 warnings, over 445 documents. Its 8 info lines are each
application's copy of `svc-kac` accepting `critical-service-is-alerted`. The `staleness-loud` warnings of the last run
have gone, because the runbook was rehearsed on 2026-10-29.

**The sizes grew with the records under `examples/`.** Since the last run, `examples/dog-fooding` gained 2 deviations
and a fix, and 2 of its runbooks became fixes. Each application has 3 more records, so 8 applications have 24 more.
#1307 added `std-CI.SCAN`, which is the extra `.jsonl` line and the 48 characters of build index.

**The timings moved by more than a quarter, and this run does not explain why.** Each command took about 1.7 times as
long. The corpus has 6% more documents, which does not account for that. The machine was not idle: its load average was
5, with a virtual machine using more than one core. The size half needs timing again on an idle machine before the move
is read as a change in `kac`.
